# Limitations of this research

What the measurements do not cover, stated so that no conclusion is read wider
than its evidence.

## Not measured

- **Real drawings.** The corpus is 38 synthetic documents, the largest a 200-page
  A4 set and a 10-sheet A1 set, all generated by
  `scripts/make-m6-fixtures.mjs`. No customer or project file was used. A real
  A1 drawing carries far more vector content than these do, so the *preview*
  numbers (which depend only on raster size) transfer, while the *document
  graph* numbers do not — which is precisely why [`budget.md`](budget.md)
  refuses to propose a memory bound.
- **Performance on real hardware.** Timings were taken on one machine, headless,
  and are MEASURED_ONLY throughout.
- **Very large page counts.** 200 pages is the largest measured. Nothing was run
  at 1,000 pages, and the linear fit is not asserted beyond the measured range.
- **PDF 2.0 features, tagged-PDF conformance, accessibility.** `/StructTreeRoot`
  was measured only as present-or-absent, not for validity.
- **Encryption beyond refusal.** The encrypted fixture proves the loader refuses
  it; nothing about decryption or permissions was researched.

## Measured in a way that has a caveat

- **The ownership measurement is a shape, not production's exact path.**
  `supersededPreview` starts two renders with `Promise.all`; production instead
  re-enters `handleExtractUpload` when a second file is chosen. What the result
  shows is that nothing in the component decides which run owns the screen, so
  the last writer wins. It does not reproduce production's re-entry sequence.
- **The object-URL measurement assigns `link.href` exactly as production does
  but does not click it**, because a real download would leave files behind in
  CI. It therefore proves that `revokeObjectURL` is never called — the question
  asked — and proves nothing about the click.
- **Heap figures are advisory.** `performance.memory` is Chrome-only, quantised,
  and moves with collection nobody controls. Every bound in this research comes
  from retained string length and canvas RGBA arithmetic instead.
- **The "orphan page" count is a count of page objects outside the page tree.**
  It does not measure how many *bytes* those pages cost, which depends on what
  they reference. The disclosure argument in
  [`extract-contract.md`](extract-contract.md) rests on their presence, not
  their size.

## Instrument defects found during this research

Recorded because they nearly produced wrong conclusions, and because a gate that
has never been wrong has usually never been checked.

1. **`structure.mjs` returned early when a document had no `/AcroForm`**, so its
   orphan-widget scan never ran in the one situation it exists for — a page
   copied away from its form. Two BASELINE-FAIL rows read "0 orphan widgets"
   and looked like the product behaving well. Fixed; the same rows then measured
   2 orphan widgets, which is the real finding.
2. **The output-ceiling probe used a hard-coded 4,096 B** against an artifact
   that turned out to be 3,462 B, so it asserted that a file *under* the ceiling
   was over it. Replaced with a boundary derived from the artifact itself — the
   same correction M5 made for its archive guard.
3. The first fixture generator drew a "scanned" page by splicing a second
   content stream in behind pdf-lib's own, which would have made the page's
   drawing order depend on an implementation detail. Rewritten to use pdf-lib's
   operator helpers.
4. **The preservation matrix asserted something the evidence had already
   contradicted.** It said an internal link to a kept page was "preserved,
   retargeted" while `evidence.json` recorded `inDocumentDests: 0` in every
   Extract case. The evidence was right; the sentence was written from what
   `copyPages` ought to do. This is the failure mode worth naming: a document
   that describes a measurement it did not read. The per-shape fixtures in
   RF-R1 exist so the claim now has one case each rather than one summary.
5. `extractWithForm` returned `{ status: 'REFUSED', ...plan }`, and the spread
   overwrote the status with the plan's own `'REFUSE'`. A refusal that worked
   correctly — right code, right reason — failed its own check, and for one run
   the gate reported the straddling-field case as broken when it was not.
6. A gate section was written against a section heading copied from the M5 gate
   (`// ---- 9. ownership`) that does not exist in this file. The edit was
   rejected rather than applied, which is the good failure; the bad version of
   the same mistake would have been an anchor that matched something else.
7. **A volatile number was stored in the box reserved for stable ones.** Running
   the research gate twice from one committed source reported that structural
   classifications were *not* identical. The whole difference was two artifact
   byte counts, each off by one: `extractMatrix.middle` 1,464 → 1,463 and
   `mergeMatrix['B+A']` 2,669 → 2,668. The legacy routes are reproduced with
   pdf-lib's defaults, so `updateMetadata: true` writes a fresh `/ModDate` on
   every run and the serialised offsets move a digit with it. Nothing
   structural moved. The counts are now recorded as `bytesMeasuredOnly`, which
   is what they always were; had they been named that from the start, the
   stability check would have been answerable on the first attempt instead of
   looking like non-determinism in the measurements.

## A note on `researchTreeDirty`

Both evidence files record `workingTreeDirty` and `researchTreeDirty`, and both
are `true`. Neither means there is uncommitted work hiding behind these numbers,
and the reason is worth stating so the flags are not misread in either
direction.

`workingTreeDirty` is true because the repository carries untracked directories
that predate this research — `public/tessdata/`, `public/tesseract/`, `spike/`.
It would be true whatever this branch did. It is still recorded rather than
filtered, because M5's RF-M4 established that evidence integrity may not be
bought by telling git to ignore what it can see.

`researchTreeDirty` is true for a reason that cannot be removed: **a gate that
writes its own evidence file makes the tree dirty by running.** At the moment
the flag is computed, the `evidence.json` being written is itself an uncommitted
change. The honest reading is "these numbers were produced by the source at
`testedResearchHead`, and the evidence file recording them was written
afterwards" — which is what a research gate does, and which the commit that
follows resolves.

What the flag would usefully catch is a *different* case: numbers quoted in the
documents that no committed script can reproduce. Against that, the binding is
`testedResearchHead` plus committed scripts, and both are present.
